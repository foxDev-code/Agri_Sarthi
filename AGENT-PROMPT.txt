VISUAL DIRECTION
----------------
Create a cinematic academic-intelligence website called AgriSarthi by default.
It should feel like moving through a carefully lit miniature botanical
world, with restrained product UI floating within it.

Use near-black, forest green, muted sage, warm off-white and selective
yellow-green highlights. Combine a clean sans serif such as Inter with
Instrument Serif for expressive serif phrases. Use large, carefully spaced
headings, short supporting copy, generous negative space and small labels.

Scenery: photorealistic bonsai trees, richly textured moss, curved branches,
transparent glass with moss inside, glowing particles, and carved stone.
Use directional light, foreground/background depth and soft dark edges.
Cards should have subtle translucent surfaces, thin borders, restrained
blur and rounded corners. Keep their text readable over the scenery.

Do not replace the reference with a generic collection of landing-page
cards, excessive gradients, neon outlines, stock-photo sections or random
decorative movement. Match the composition and timing that the reference
actually supports.

IMPLEMENTATION REQUIREMENTS
---------------------------
- Choose a simple maintainable stack. Preferred starting point: Vite,
  semantic HTML, CSS, JavaScript, GSAP with ScrollTrigger/ScrollToPlugin,
  and Three.js for the particle globe. React is acceptable if appropriate
  to the existing project. Use installed design and animation skills when
  relevant, and read their actual instructions before applying them.
- Use a shared pinned desktop stage and a coherent master timeline.
  Connect animation progress to native scrolling with smooth scrubbing.
  Reversing the scroll must reverse the same poses and transitions.
- Preserve persistent objects across connected scenes rather than fading
  between unrelated duplicates. Build intermediate transition states,
  not only the ten finished section layouts.
- Provide an optional Play/Pause tour and accessible chapter controls.
  Manual scrolling, touch, navigation keys or other page interactions
  should interrupt the tour reliably. Chapter links must land on readable
  settled states, including after resizing or loading a URL fragment.
- Use transform and opacity for most motion. Limit blur and mask animation
  to the small number of transitions needed for reference fidelity.
  Keep frequent UI interactions fast and independent of cinematic timing.
- Load expensive WebGL code when needed, limit device pixel ratio, and
  stop rendering when hidden or outside its active scene. Include a static
  fallback for WebGL failure. Avoid unnecessary dependencies and CDN calls.
- Provide a native stacked layout for small screens. Respect reduced-motion
  preferences. Do not shrink desktop content until mobile text is unreadable.
- On breakpoint changes, clean up pins, transforms, split text, duplicated
  decorative objects, event listeners and inert states. Restore correct data.
- Use accessible labels, heading structure, keyboard navigation, visible
  focus, meaningful buttons and appropriate dialogs. Decorative duplicates
  must not become extra keyboard stops or screen-reader content.
- Implement meaningful local demo interactions where a backend is absent.
  Clearly label sample AI/data and local-only actions. Never imply that
  authentication, payments or email delivery are connected when they are not.
